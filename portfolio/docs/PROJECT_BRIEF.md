## Core concept
A cinematic desk / room / workbench hub, similar to a solo-player game menu. Four objects act as portals:

| Object | Section | Idle / Hover behavior | Click transition concept |
| --- | --- | --- | --- |
| Robot | Robotics | Existing idle/gesture clips and highlight | Camera approaches robot → Robotics mini world |
| Basketball | Personal / About | Restrained movement/highlight | Camera approaches ball → personal/court mini world |
| Camera | Photography / Creative | Label/highlight or verified existing reaction | Camera approaches object → photography mini world |
| Microchip or development object | Software Projects | Selected existing emissive/press behavior | Camera approaches object → software mini world |

Every portal needs idle, hover/focus, click/keyboard/touch selection, a mini-world state and return to the main desk. Exact destination composition and assets remain proposed, not implementation instructions. No source is assumed to contain unverified authored animations.

## Experience principles

Actual browser screenshots must be compared with these references during authorized visual work. Proprietary game assets are excluded from production reuse.

- Make the hub feel like a coherent 3D place; reuse licensed scene assets and existing interaction/camera implementations.
- Basketball is one personal section, never the site-wide theme.
- Prioritize reusable 3D scene code and asset-based integration. Do not design a typography-first landing page or separate specimen cards.
- Project case studies must be easy to read and navigate, with direct URLs, technical diagrams/screenshots as applicable, and clear GitHub/demo links.
- Hover, focus, keyboard, touch, and reduced-motion alternatives are all first-class.
- Camera-led transitions into distinct mini worlds; visible return path, interruption and reduced-motion alternatives. Direct content links remain immediate.
- Performance and graceful fallback are required; marketing motion must not block content.
